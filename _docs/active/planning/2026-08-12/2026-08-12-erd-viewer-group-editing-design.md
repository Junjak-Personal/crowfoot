# 그룹 편집을 손에 익게 만들기 — 선택 모델 · 선택 HUD · 카메라

- 상태: planning
- 토픽: `erd-viewer`
- 작성: 2026-08-12
- 작업 표면: `frontend/packages/erd-core` (`ErdContent`, `TableGroupNode`, `useTableSelection`)

## 문제

그룹 기능은 다 있는데 쓰기가 불편하다. 세 가지가 겹쳐 있다.

### ① 무엇을 선택한 건지 알 수 없다

지금 선택 상태는 **항상 "테이블 n개"** 하나뿐이다. 그룹 헤더를 클릭하면
`selectMembers()`가 멤버 테이블들을 선택한다 — 즉 **그룹을 선택하는 방법이 없다.**
"그룹을 골랐다"와 "그 안의 테이블들을 골랐다"가 같은 상태라서, 다음 명령이 무엇에
적용될지 화면만 봐서는 알 수 없다.

### ② 몇 개가 선택됐는지 보여주지 않는다

`selectedTableCount`는 이미 계산하고 있지만 **컨텍스트 메뉴 항목을 켜고 끄는 데만
쓴다.** 화면에 숫자가 나오지 않는다. 라쏘로 훑고 나서 몇 개가 잡혔는지 확인할
방법이 노드 테두리를 세는 것뿐이다.

### ③ 기존 그룹에 테이블 하나를 넣을 수 없다

| 동작 | 지금 |
|---|---|
| 새 그룹 만들기 | `⌘G` / 테이블 우클릭 → `Group selected tables` (2개 이상) |
| **기존 그룹에 하나 추가** | **없음** |
| 기존 그룹에서 하나 제외 | 테이블 우클릭 → `Remove from "X"` (있긴 한데 메뉴에 묻혀 있음) |
| 그룹 해제 | `⌘⇧G` / 헤더 우클릭 → `Ungroup` (확인 모달) |

추가가 없으니 테이블 하나를 옮기려면 **그룹을 해제하고 다시 만드는 것**밖에 없다.
이름·색까지 다시 지정해야 한다.

### ④ (겸사) 테이블을 클릭하면 카메라가 움직인다

`useTableSelection.selectTable`이 `displayArea === 'main'`이면
`fitView({ maxZoom: 1, duration: 300, nodes: [{ id }] })`를 부른다.
**이미 보고 있는 테이블을 클릭했는데 캔버스가 그리로 확대·이동한다.** 그룹을
편집하는 동안은 이게 계속 방해가 된다.

## 결정

| 질문 | 결정 | 근거 |
|---|---|---|
| 선택 모델 | **`{kind:'group'} \| {kind:'tables'}` 명시적 2단** | ①의 원인이 "상태가 하나뿐"이라서다. 표시를 고쳐도 상태가 하나면 여전히 모호하다 |
| 명령을 어디에 둘까 | **선택 HUD (하단 떠 있는 바)** | ②와 ③을 한 표면이 덮는다. "무엇이 선택됐나"와 "그래서 뭘 할 수 있나"는 같은 자리에 있어야 한다 |
| 우클릭 메뉴 | **그대로 둔다** | HUD는 *선택*에 대한 명령, 우클릭은 *그 항목 하나*에 대한 명령. 범위가 다르다 |
| 카메라 | **캔버스 클릭은 안 움직이고, 사이드바·팔레트 클릭은 움직인다** | 안 보이는 걸 찾아간 경우에만 프레이밍이 정보다 |
| 되돌리기 | **범위 밖** | 히스토리 스택이 없다. 여기 끼우면 작업이 두 배 — 별도 과제 |

## A. 선택 HUD

React Flow `<Panel position="bottom-center">`. **선택이 없으면 렌더하지 않는다.**

```
┌──────────────────────────────────────────────────────────┐
│  테이블 3개 선택 · 2개는 Core 소속                          │
│  [그룹 만들기 ⌘G]  [그룹에 추가 ▾]  [그룹에서 빼기 ▾]        │
└──────────────────────────────────────────────────────────┘
```

```
┌──────────────────────────────────────────────────────────┐
│  그룹 「Core」 · 테이블 5개                                 │
│  [이름 바꾸기]  [색 ▾]  [안으로 들어가기 ⏎]  [해제 ⌘⇧G]     │
└──────────────────────────────────────────────────────────┘
```

버튼은 **선택 상태에서 유도**한다. 조건이 안 맞으면 비활성이 아니라 **없다** —
비활성 버튼은 왜 못 쓰는지를 설명하지 못한다.

| 조건 | 나오는 것 |
|---|---|
| 테이블 2개 이상 | `그룹 만들기` |
| 테이블 1개 이상 + 그룹이 하나라도 존재 | `그룹에 추가 ▾` |
| 선택 중 하나라도 어떤 그룹 소속 | `그룹에서 빼기 ▾` |
| 그룹 선택 | `이름 바꾸기` `색` `안으로` `해제` |

`그룹에 추가 ▾` / `그룹에서 빼기 ▾`는 **그룹 목록 드롭다운**이다. 다중 소속을 이미
지원하므로(한 테이블이 여러 그룹에 들어갈 수 있다) 목록에서 고르는 형태가 맞다.

### 미리보기 (pegboard의 "규칙 암시")

`그룹에 추가 ▾` 목록의 한 줄에 **호버하면 결과 박스를 점선으로 미리 그린다** —
선택된 테이블까지 포함하도록 커진 박스를, 그 그룹 색으로. 클릭해야 실제 커밋된다.
"인터렉션 중엔 preview, 종료 시 실 데이터" 원칙 그대로다.

박스 기하는 이미 매 렌더 `resolveGroupMemberIds` → `getNodesBounds` →
`padGroupRect`로 파생되므로, 미리보기는 **멤버 목록에 후보를 더해 같은 함수를 한 번
더 부르는 것**이다. 새 기하 코드가 필요 없다.

> 이 미리보기가 비싸지면 **여기가 자르는 지점이다.** 나머지는 미리보기 없이도 동작한다.

## B. 2단 선택

```
그룹 헤더 클릭        → 그룹 선택        (박스 강조, HUD는 그룹 명령)
그룹 헤더 더블클릭    → 안으로 들어감    (개별 테이블 선택 가능)
박스 안 테이블 클릭   → 안으로 들어감 + 그 테이블 선택
Esc                  → 한 단계 밖으로
```

상태는 `ErdContent`의 로컬 state 하나로 둔다 — `menu`, `connecting`,
`pendingUngroup`이 이미 그렇게 살고 있다.

```ts
type CanvasSelection =
  | { kind: 'tables' }              // React Flow 의 node.selected 가 진실
  | { kind: 'group'; groupId: string }
```

`kind: 'tables'`일 때 실제 목록은 React Flow가 계속 들고 있게 둔다. **선택 목록을
복제해 두 곳에서 관리하면 어긋난다** — 그래서 여기서는 *종류*만 기억한다.

### 딸려오는 수정

- `TableGroupNode`의 헤더 클릭이 `selectMembers()` 대신 그룹을 선택한다.
  **헤더 드래그는 그대로 동작한다** — 드래그는 `memberIds`로 직접 움직이지
  선택 상태를 보지 않는다. 오히려 "선택했다가 옮긴다"는 두 단계가 하나로 준다.
- `handleGroupSelected`(⌘G) · `handleUngroupSelected`(⌘⇧G)가 지금은
  `selectedIdsOf('table')`에서 의도를 읽는다. **그룹이 선택된 상태에서는 빈 배열이
  되므로 반드시 같이 고쳐야 한다** — 안 고치면 ⌘⇧G가 조용히 아무것도 안 한다.
- `⌘⇧G`가 그룹 선택 상태면 그 그룹만, 테이블 선택 상태면 지금처럼
  `groupsClaiming`으로 찾는다.

## C. 카메라

`useTableSelection`을 둘로 나눈다.

| | 카메라 | 쓰는 곳 |
|---|---|---|
| `selectTable` | 안 움직인다 | `ErdContent.handleNodeClick` (캔버스 클릭) |
| `revealTable` | `fitView` 로 프레이밍 | `LeftPane/TableNameMenuButton`, `CommandPalette/useTableOptionSelect` |

호출부 3곳을 같이 고친다(선택 파라미터로 분기하지 않는다 — CLAUDE.md).

`useInitialAutoLayout`(딥링크 첫 프레이밍)과 `useQueryParamsChanged`(뒤로가기)의
`fitView`는 **그대로 둔다.** 둘 다 "안 보이는 것을 찾아간" 경우다.

## 범위 밖

- **되돌리기 / 히스토리 스택** (pegboard의 트랜잭션·롤백). 지금 뷰어에 없다. 별도 과제.
- **테이블을 그룹 박스로 드래그해 넣기.** A가 만드는 명령의 단축 경로일 뿐이라 나중에
  붙여도 손해가 없다.
- **라쏘 선택** — `selectionOnDrag={editMode}`로 **이미 된다.** 만들 것 없음.
- 서버 임시저장 · 동시 편집 충돌 — 이 뷰어는 정적 SPA다. 해당 없음.

## 구현 후 정정 (2026-08-12)

**`onDoubleClick`은 캔버스 안에서 아예 도착하지 않는다.** React Flow의 zoom pane에
d3-zoom이 `dblclick`을 잡아 double-click-to-zoom을 돌리면서 전파를 끊는다. React는
루트에서 이벤트를 듣기 때문에 캔버스 안 어떤 요소도 그 이벤트를 못 받는다.

`click`의 `event.detail`(클릭 횟수)로 바꿨다. 부수효과가 오히려 맞다 — 쌍의 첫 클릭이
이미 그룹을 선택해 두므로 중간 상태가 자연스럽다. `zoomOnDoubleClick={false}`로
끄는 방법도 있었지만, 그러면 컴포넌트가 호스트의 prop에 조용히 의존하게 된다.

**미해결 2개 다 실측으로 닫혔다.**
- `CanvasBadge`는 **우상단**, HUD는 하단 중앙 — 겹치지 않는다.
- 색·이름은 HUD에 넣지 않았다. 헤더 우클릭에 이미 있고, HUD의 일은 "무엇이 몇 개
  선택됐나"와 "소속을 어떻게 바꾸나" 둘이다.

**계획에 없던 정리 하나.** `ErdContentInner`가 biome의 인지 복잡도 상한(15)을 넘겨서
(17) 그룹 소속 명령들을 `useGroupMembership` 훅으로 뺐다. 상한이 아니었으면 안 했을
분리인데, 결과적으로는 맞는 자리다.

### 브라우저 실측 (nivoca-legacy 23테이블 / 6그룹)

| 항목 | 결과 |
|---|---|
| 캔버스 테이블 클릭 후 viewport transform | `translate(-258.566px, 250.815px) scale(0.152636)` → **동일** |
| 커맨드 팔레트에서 테이블 선택 | `scale(0.148)` → `scale(1)` 프레이밍 — **여전히 움직인다** |
| 그룹 헤더 클릭 | 박스 1개 selected, 노드 0개 selected (두 종류 배타) |
| `Select its tables` | 노드 2개 selected, 박스 0개 selected |
| `Add to ▾` 호버 미리보기 | 대상 박스 607 → 1333px, 나머지 5개 불변 |
| 클릭 커밋 후 새로고침 | 1342px 유지 (`?groups=`에 영속) |

두 번째 줄이 첫 줄을 공허하지 않게 만든다 — 카메라를 아예 죽인 게 아니라
캔버스 클릭에서만 뗀 것이다.

## 0.4.2 에서 뒤집힌 전제 (2026-08-18)

**「다중 소속을 이미 지원하므로」가 §A 의 근거였는데, 그 전제가 죽었다.** 0.4.2 부터 한
테이블은 한 그룹에만 속한다 — 박스가 멤버 bounding box 에서 파생되므로 공유 테이블은 두
박스를 반드시 교차시키고, `arrange` 는 공유 테이블을 두 컬럼에 놓지 못한다.

§A 의 표가 그만큼 줄었다.

| 이 문서 | 0.4.2 |
|---|---|
| `그룹에 추가 ▾` (드롭다운) | `Move to ▾` — 들어가는 것이 곧 나오는 것 |
| `그룹에서 빼기 ▾` (드롭다운) | `Remove from group` 버튼 하나 — 뺄 그룹이 하나뿐 |
| 미리보기 = 대상 그룹 1개 | 그룹 id → 멤버 맵 — 이동은 두 상자가 동시에 변한다 |

기존 데이터는 **읽을 때 first-wins 로 정규화**한다(`claimEachTableOnce`, `getEffectiveGroups`
한 곳). `erd arrange` 만은 정규화 대신 **거부**한다 — 계획은 물려받는 것이 아니라 지금 쓰는
것이라서.

브라우저 실측(2테이블 / 겹치는 `groups.json` 2그룹, 패키징된 0.4.2 로 빌드한 사이트):
`g1=[users]`, `g2=[users, posts]` 를 올렸을 때 상자는 `First` 10..448 · `Second` 831..1269 —
**교차 없음**. 사이드바는 `First>users`, `Second>posts`, `(2/2 visible)`.
